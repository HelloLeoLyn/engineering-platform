## 3. Manifest Direction

project.yaml 成为项目生成的主要用户输入（不再需要 Java Options 才能生成）：

| 字段 | 状态 | 语义 |
|---|---|---|
| project.id | 已有 | → artifactId 默认值 |
| project.name | 已有 | → projectName / applicationName |
| project.version | 已有 | 项目版本 |
| project.basePackage | 已有 | Java 包根 |
| project.groupId | **新增（可选）** | Maven groupId；缺省由 basePackage 前两段推导 |
| project.artifactId | **新增（可选）** | Maven artifactId；缺省 = project.id |
| project.configuration | **新增（可选）** | 资产配置值（{key: value}，语义化为"资产配置输入"；secretRef 仍走占位符，不落明文） |

原则：补齐**开发者语义字段**（groupId/artifactId），不机械暴露内部 Options（如 generatorVersion/ownership 等不进 manifest）。

## 4. CLI V1

最小 CLI（零依赖 main 类 + `ep` 命令包装；不做复杂 CLI framework）：

| 命令 | input | output | exit code | failure behavior |
|---|---|---|---|---|
| `ep validate project.yaml` | manifest 路径 | 校验结果（PASS / 错误列表） | 0=PASS；1=FAIL | 输出全部 schema 错误，不继续 |
| `ep resolve project.yaml` | manifest 路径 | EPM 摘要（capabilities/providers/quality/technology） | 0=SUCCESS；1=FAILED | 输出 ResolutionError 列表 |
| `ep generate project.yaml --output PATH` | manifest + 输出目录 | 生成文件清单 + planId | 0=SUCCESS；1=Generation FAILED；2=用法错误 | 失败停在正确层级（无半成品） |
| `ep conformance project.yaml PROJECT_DIR` | manifest + 项目目录 | ConformanceResult（PASS/FAIL + findings） | 0=PASS；1=FAIL/ERROR | 输出全部 findings |

约定：stdout 结构化结果，stderr 错误详情；所有命令读真实 assets（capabilities/ + providers/）+ 真实 registry。

## 5. Developer Workflow

目标体验：

```bash
ep validate project.yaml
ep resolve project.yaml
ep generate project.yaml --output ./my-project
ep conformance project.yaml ./my-project
cd my-project && mvn test          # BUILD SUCCESS
```

开发者全程不接触 Java API；CLI 内部复用 AssetAwareResolver / AssetProjectGenerator / ConformanceValidator（V0.2 能力零重写）。
