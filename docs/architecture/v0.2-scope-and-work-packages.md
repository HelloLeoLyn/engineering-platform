# V0.2 Scope & Work Package Plan

- **日期**: 2026-08-14 ｜ **基线**: main b7fc3c6
- **依据**: ADR-001 / system-boundary / v0.1-legacy-ownership-review / v0.2-readiness-gap-analysis

## 1. Primary Objective

**Engineering Platform V0.2 = Reusable Engineering Asset Platform**

以资产库（templates/starters/registry 数据 + Asset Contract V1）为核心，打通
Modeling → Resolution → Generation → Conformance，使真实 Java 项目可声明、可解析、可生成、可验证。

**最终验收锚点**：
```
project.yaml → reusable assets → Resolver/EPM → Generation
→ real Spring Boot project → Engineering Conformance → mvn test → BUILD SUCCESS
```

## 2. V0.2 Scope

只围绕六域：Engineering Standards / Reusable Engineering Assets / Project Modeling / Resolution / Generation / Engineering Conformance。

禁止进入：AI Dev OS 职责、Agent Runtime、OpenClaw/Codex、Approval、Retry/Timeout、Browser、MCP orchestration、Task Acceptance。

## 3. Reference Stack（第一条真实链路）

- **Runtime**: Java 25 + Spring Boot（3.x 兼容基线）
- **第一批工程能力**: web / validation / exception-handling / logging / persistence / audit
- **第一个 Provider**: MyBatis-Plus
- **Quality**: Q3
- 目的：只证明第一条真实资产链路，不覆盖全技术栈。

## 4. Asset Model（最小 Asset V1）

一个 Asset 至少包含：

| 元素 | 说明 |
|---|---|
| manifest | 机器可读资产声明（YAML，接入现有 schema 体系） |
| identity/version | id + version（可被 Registry 索引、被 project.yaml 引用） |
| dependencies | 外部依赖（如 Maven GAV）与资产间依赖 |
| compatibility | platformVersion / Java / Spring Boot / provider 兼容声明 |
| templates/files | 资产携带的文件/模板（项目结构、代码骨架） |
| configuration | 应用配置片段（application.yml、属性） |
| conformance rules | 该资产的合规规则（结构/依赖/配置要求） |
| tests | 资产附带测试模板/基线 |
| documentation | 使用说明（guides） |

**明确不做**：插件 SDK、Marketplace。

## 5. Work Packages（6 个）

### V02-WORK-001 — Asset Contract V1
- **目标**: 定义 Module / Capability / Provider / Template 真正可消费的资产契约（schema + Java 模型 + validator）
- **验收**: 至少一套 valid/invalid asset contract fixtures 可被 validator 校验（exit 0 / 拒绝）

### V02-WORK-002 — Reference Asset Set V1
- **目标**: 建立第一套真实资产：web / validation / exception-handling / logging / persistence / audit + MyBatis-Plus provider
- **验收**: Registry 不再为空壳；Resolver 有真实资产输入（capabilities/providers/modules 有数据）

### V02-WORK-003 — Asset-aware Resolution
- **目标**: 现有 Resolver 真正消费 Asset metadata（dependency / capability / provider / compatibility / configuration / quality）
- **验收**: 真实 project.yaml（引用 V02-WORK-002 资产）→ 有效 EPM（无 MISSING 错误）

### V02-WORK-004 — Asset-driven Generation
- **目标**: Asset 真正产生项目内容：Spring Boot 结构、pom 依赖、application 配置、base package、标准 exception handling、validation、logging、persistence 配置、audit 基线、测试
- **验收**: Generator 产出真实可编译项目（不要求已通过 Conformance）

### V02-WORK-005 — Engineering Conformance V1
- **目标**: 验证生成项目符合 Platform Standard：Java/Spring 基线、项目结构、依赖规则、required capabilities、provider 兼容、required config、required tests
- **验收**: ConformanceResult PASS/FAIL 可执行（生成项目 → 明确结论）

### V02-WORK-006 — Real Project E2E
- **目标**: 完整真实闭环：project.yaml → resolve → generate → conformance → mvn test
- **验收**: 生成项目 `mvn test` = BUILD SUCCESS；并增加 failure-path E2E（资产缺失/依赖冲突/结构违规 → 正确 FAIL）

依赖顺序：001 → 002 → 003 → 004 → 005 → 006（005 可与 004 并行起步；006 依赖全部）。

## 6. Anti-Goals（V0.2 不做）

1. 多技术栈（只 Java/Spring）
2. 前端资产体系
3. Marketplace
4. 复杂插件 SDK
5. 远程服务化（EP 仍为库/本地能力）
6. OpenClaw Adapter / Codex Adapter
7. Browser / Approval / AI planning
8. Legacy 大清理（V0.1 Legacy 继续 freeze，仅阻碍主目标时做最小兼容处理；不设独立 Legacy cleanup WP）

## 7. Legacy 处理

- V0.1 Exploration Legacy：**继续 freeze**。
- 仅当明确阻碍 V0.2 主目标时才做最小兼容处理（如 Resolver 消费 Asset 需调整的既有契约）。
- 不把 Legacy cleanup 作为独立 Work Package。

## 8. Definition of Done（V0.2 完成必须全部满足）

1. 至少 6 个真实工程资产（web/validation/exception-handling/logging/persistence/audit）
2. 至少 1 个真实 Provider（MyBatis-Plus）
3. Registry 有真实资产（非空壳）
4. project.yaml 能引用真实资产
5. Resolver 产生真实 EPM（无 MISSING）
6. Generator 生成真实 Spring Boot 项目
7. 自动装配 Maven dependencies
8. 自动生成必要配置/代码/测试
9. Engineering Conformance 可执行（PASS/FAIL）
10. 生成项目 `mvn test` = BUILD SUCCESS
11. CI 跑真实 E2E（V02-WORK-006 纳入 .github/workflows）
12. 不依赖 AI Dev OS Runtime（EP 独立闭环）
