## 1. Primary Objective

**Engineering Platform V0.4 = Enterprise Application Foundation**

让"生成的项目"从空骨架变成**可登录、有用户/角色/权限/组织/数据权限/菜单/字典/操作日志的企业后端**：

```
project.yaml（声明 auth+user+role+permission+org+data-permission+menu+dict+operation-log）
→ ep generate
→ 生成含企业基座的可编译 Spring Boot 项目（登录/权限校验/组织/数据权限/字典/操作日志/迁移 SQL）
→ ep conformance PASS
→ 生成项目 mvn test BUILD SUCCESS
→ 真实 E2E：启动 → 登录 → token → 受保护 Product API → RBAC → 数据权限 → 操作日志落库 全链路 PASS
```

- 生成项目 mvn test BUILD SUCCESS（含新增测试）
- 既有 276 tests 全绿不回退；Python validators 全 PASS
- 真实 E2E 全链路证据：generate → boot → login → token → protected Product API → RBAC → Data Permission → Operation Log persistence → Conformance PASS → mvn test BUILD SUCCESS

- **Reference Product CRUD**（定位：仅用于验证 Platform Core / Authentication / RBAC / Organization / Data Permission / Operation Log 能被真实业务模块消费；**不建设通用 CRUD Generator**）

- Tenant / File / Cache / Scheduled Job / Notification
- Event/Notification/Print/Excel/Observability 资产（§4 剩余能力）
- Spring Boot 升级/降级（沿用 v0.3 技术基线）

## 3. Manifest 方向

project.yaml 声明企业能力（与既有 capabilities 声明同机制）：

| 字段 | 状态 | 语义 |
|---|---|---|
| capabilities: [auth, user, role, permission, organization, data-permission, menu, dict, operation-log] | 复用现有列表声明 | 企业资产按 Capability+Provider 架构注册 |

## 4. Work Packages（V04-WORK-001 ~ 006）

### V04-WORK-001 — Platform Core
- **目标**：统一后端基础契约可生成（兑现 §2/§11 最小核心）
- **范围**：ApiResponse/PageResult/PageQuery/RequestContext/PlatformException/ErrorCode（已有资产补全）/IdGenerator/CurrentClock → 作为资产模板（生成到 {package}/common/core/）
- **DoD**：project.yaml 声明 → 生成含 core 契约文件 → conformance required-files PASS → 生成项目 mvn test PASS
- **禁止**：不建万能 BaseEntity；技术框架不进 core

### V04-WORK-002 — Authentication + User/Role/Permission
- **目标**：认证与 RBAC 可生成
- **范围**：4 项资产 + 模板（实体/Mapper/Service/Controller/迁移 SQL：sys_user/sys_role/sys_user_role/sys_permission）+ BCrypt 登录 + token 签发/校验拦截器 + @RequirePermission 注解 + 统一无权限响应
- **DoD**：声明 4 能力 → 生成项目含登录接口（真实可调）、受保护接口校验生效、迁移 SQL 完整、mvn test PASS
- **禁止**：不引入 Spring Security 全家桶；不做数据权限/组织（属 WORK-003）

### V04-WORK-003 — Organization + Data Permission
- **目标**：组织维度与数据权限 V1 可生成，且**查询层真实 enforcement**
- **范围**：
  - organization：sys_dept 迁移 + 实体/服务/接口（department tree）
  - data-permission：范围枚举 **ALL / DEPARTMENT / DEPARTMENT_AND_CHILDREN / SELF** + 数据范围解析器（由当前登录用户角色/部门计算） + **查询层 SQL 条件注入（MyBatis-Plus QueryWrapper 条件拼接或拦截器）**，业务查询必须走数据范围包装
  - 迁移 SQL + 示例（用户与部门关联、角色与数据范围关联）
- **DoD**：声明 2 能力 → 生成项目含 dept 树接口；数据权限四种范围分别实测：同一查询在不同范围下返回不同行集（SELF 只返回本人数据、DEPARTMENT 返回本部门、DEPARTMENT_AND_CHILDREN 含子部门、ALL 全量）→ mvn test PASS
- **禁止**：不允许仅 enum/annotation 即算完成；不实现跨库/多租户数据权限

### V04-WORK-004 — Menu + Dictionary + Operation Log
- **目标**：企业基础数据能力可生成
- **范围**：menu/dict/operation-log 3 项资产 + 模板 + 迁移 SQL（sys_menu/sys_dict_type/sys_dict_item/sys_oper_log）+ 操作日志切面（复用 V0.2 audit 资产思路，语义对齐"用户操作日志"，记录操作人/接口/参数/结果/时间）
- **DoD**：声明 3 能力 → 生成项目含菜单/字典接口、操作日志切面落库、mvn test PASS
- **禁止**：不做菜单可视化设计器；不引入完整审计/证据链

### V04-WORK-005 — Enterprise Asset Integration + Reference Product CRUD
- **目标**：企业资产在生成链路中正确装配，并用真实业务模块消费验证
- **范围**：
  - 生成器装配：AssetRepository/AssetProjectGenerator 支持企业资产装配（依赖补齐：spring-security-crypto 仅 BCrypt）、secretRef 占位不落明文、密码字段默认 BCrypt 校验、资产间依赖（operation-log→audit/logging、permission→auth、data-permission→organization）
  - **Reference Product CRUD**（定位仅为验证宿主）：product 模块声明 → 生成标准 CRUD（Controller/Service/Mapper/DTO/迁移/权限注解）→ 该模块消费 Platform Core（统一响应/分页）+ Authentication（登录可调）+ RBAC（权限注解）+ Organization（数据范围字段）+ Data Permission（列表按范围过滤）+ Operation Log（写操作落日志）
- **DoD**：真实 project.yaml 全量声明 → resolve 闭包正确 → generate 产出全部企业文件 → conformance PASS → 生成项目编译+测试通过；Product CRUD 的列表接口在 SELF/DEPARTMENT/ALL 三种登录用户下返回不同数据（数据权限消费实证）
- **禁止**：**不建设通用 CRUD Generator**（留给 V0.6）；不生成复杂业务规则/状态机；不做前端页面（V0.5）

### V04-WORK-006 — Real Enterprise Backend E2E + Release Gate
- **目标**：V0.4 发布门禁，全链路真实证据
- **范围**：backend 骨架构建入 CI（Java 25 Build + Test 扩到生成项目）、全量回归（276 + 新增）、真实 E2E、V0.4 Release Checklist
