# V0.5 Scope & Work Package Plan — Enterprise Application Foundation

- **日期**: 2026-08-15 ｜ **基线**: v0.4.0（main d17e7e8）｜ **性质**: PLANNING ONLY（未写代码、未碰 git）
- **依据**: V0.4 Post-Release Capability Audit（Frontend=NOT DONE / 管理 API 只读 / 模块生成器不存在）+ V0.7 前端技术主线 + 用户 2026-08-15 规划指令
- **核心目标**: 让 Engineering Platform 从"能生成可运行企业后端"提升为"能生成一个可在浏览器中真实使用的基础企业管理应用"

## 1. Primary Objective

**Engineering Platform V0.5 = Enterprise Application Foundation**

```
project.yaml → ep generate → generated backend + frontend
→ backend boot → frontend build/start → browser login
→ dynamic menu → enterprise management pages → Product management
→ frontend permission control → backend RBAC/Data Permission final enforcement
→ browser E2E PASS → backend tests PASS → frontend tests/build PASS → conformance PASS
```

**关键定位**：前端是后端企业基座（Auth/RBAC/Data Permission/Menu/Dictionary/OpLog）的**真实消费端**；后端仍是最终安全边界。V0.5 不解决全部 Gap（模块生成器留 V0.6）。

## 2. Frontend Technology Baseline

沿用 V0.7 已决定主线（§6 Technology Stack），不承担大规模技术升级：

| 项 | 基线 |
|---|---|
| 框架 | Vue 3 + TypeScript |
| 构建 | Vite |
| 路由 | Vue Router |
| 状态 | Pinia |
| UI | Element Plus |
| 测试 | Vitest（单测）+ Playwright（浏览器 E2E） |
| 包管理 | pnpm（lockfile 入库，deterministic） |

禁止：React / Next.js / Nuxt / 第二套前端栈。

## 3. Frontend Architecture

```
frontend/                    （生成项目内，与 backend/ 并列）
  apps/
    admin-web/               （可启动的管理端应用：main.ts / router / App.vue）
  packages/
    request/                 （平台 Request Client：base URL/Auth header/401/错误映射）
    ui/                      （平台 UI 组件：AppTable/AppForm/PermissionButton/DepartmentTree/DictionarySelect）
    auth/                    （登录/token 持久化/current-user/logout）
    permission/              （v-permission 指令 + PermissionGuard + 动态菜单）
    shared/                  （类型/常量/工具，最小化）
```

**边界原则**：Business Feature（User/Role/Department/Menu/Dictionary/Product 页面）在 apps/admin-web 内按 feature 目录组织；可复用平台能力收进 packages。**不为架构漂亮创建大量空 package**——每个 package 必须有真实消费者。

## 4. Frontend Asset-first

前端不硬编码进 Generator，继续复用 Engineering Asset 机制。规划 5 个 Frontend Asset（粒度可实施时调整）：

| Asset | 内容 |
|---|---|
| frontend-shell | 应用骨架（main.ts/bootstrap/layout/sidebar/header/content/loading/error-page/not-found）+ Vite/Vue Router/Pinia/Element Plus 基线 |
| frontend-auth | Login Page、token 持久化、logout、current-user、401 处理、登录重定向 |
| frontend-permission | v-permission 指令、PermissionGuard、动态菜单（消费 GET /api/menus/me） |
| frontend-enterprise-management | 管理页面集（User/Role/Department/Menu/Dictionary/OperationLog 查询）+ AppTable/AppForm/DictionarySelect/DepartmentTree |
| frontend-product-reference | Product 全栈 feature（list/search/create/edit/detail/disable + 权限按钮 + 字典状态） |

每个 Asset 的 asset.yaml 至少含：dependencies（依赖后端能力资产 + 前端基础资产）/compatibility/files（Vue SFC/TS/路由注册）/configuration/routes（前端路由元数据）/permission metadata（页面所需权限码）/tests/conformance。**不设计 Frontend Plugin SDK**。

## 5. App Shell

- application bootstrap（Vue 实例、Pinia、Router、Element Plus 注册）
- main layout（sidebar + header + content area + loading）
- error boundary / error page / not-found
- responsive baseline（最小：侧栏折叠适配窄屏）
- 不做复杂 Design System

## 6. Authentication UI

- Login Page（username/password）
- 成功 → token 持久化（localStorage，key 由生成配置决定）
- logout（清 token + 跳登录）
- current-user 加载（GET /api/users/me → Pinia store）
- 401 统一处理（Request Client 拦截 → 跳登录）
- 登录重定向（回跳原路由）
- **后端 Authentication 是最终真实认证来源；前端不复制密码/Token 验证逻辑**

## 7. Request Client

```
Business Feature → Platform Request Client → HTTP
```

- base URL（Vite env / 生成配置）
- Authorization header 注入（Bearer token）
- 401 统一处理（清 token + 跳登录）
- 稳定错误映射（后端 ApiResponse/ErrorCode → 前端错误消息）
- request/correlation metadata 透传（如后端支持）
- **业务页面禁止直接 axios/fetch 业务调用**（前端 Conformance 检查）

## 8. Router + Menu

- Vue Router + 动态菜单：登录后从 `GET /api/menus/me` 获取真实菜单构建导航
- route metadata（code/permissionCode/icon/sort）
- permission-aware route 可见性（无权限路由不可见 + 路由守卫拦截）
- **前端 Menu ≠ Authorization**：按钮/菜单隐藏只是体验；后端 RBAC 是最终安全边界

## 9. Frontend Permission

- `v-permission` 指令（按钮/操作可见性）
- PermissionGuard（路由/页面可见性）
- 权限状态来自后端返回（GET /api/users/me 的 permissions 或菜单树）
- **禁止把前端权限当安全边界**；后端 403 兜底（E2E 验证前端绕过仍 403）

## 10. Platform UI Components

V0.5 必做：

| 组件 | 用途 |
|---|---|
| AppTable | 列表/分页（封装 Element Plus Table + Pagination） |
| AppForm | 创建/编辑表单（字段 schema 驱动，最小实现） |
| PermissionButton | 权限可见按钮 |
| DepartmentTree | 部门树选择 |
| DictionarySelect | 字典下拉（消费 /api/dictionaries/{code}/items） |

按需：Pagination（AppTable 内置）/ SearchForm / ConfirmAction。**不重造 Button/Input/Dialog/Table/Select**（Element Plus 提供）。

## 11. Enterprise Management APIs（后端补齐）

V0.4 部分能力只有查询面，V0.5 补齐基础管理 API（只做 UI 所需，不做破坏性接口）：

| 资源 | 补齐 |
|---|---|
| User | list/page、create、update basic、enable/disable、assign roles、assign department |
| Role | list、create/update、enable/disable、assign permissions、DataScope configuration |
| Permission | query/list（稳定 code governance：系统 reserved code 只读，禁止随意改删） |
| Department | tree、create、update、enable/disable、parent selection（保持 self-parent/cycle 校验） |
| Menu | tree、create/update、enable/disable、permissionCode binding、sort |
| Dictionary | Type + Item 的 list/create/update/enable/disable/sort |
| Operation Log | 保持 read/query（分页/过滤：time/user/operation/resource/result/requestId） |

**安全原则**：密码初始化/重置有安全边界，**不明文展示已有密码**；Permission 的 create/delete 需按稳定 code governance 设计（默认只允许查询 + 由 seed/管理链路控制）。

## 12. Enterprise Management UI

apps/admin-web 内 feature 页面：

- **User Management**：列表/分页、创建、编辑基本信息、启用/禁用、分配角色、分配部门
- **Role / Permission Management**：角色列表/创建/编辑/启用/禁用/分配权限/DataScope 配置；权限只读列表
- **Department Management**：部门树 + 创建/编辑/启用/禁用/选择父级
- **Menu Management**：菜单树 + 创建/编辑/启用/禁用/权限码绑定/排序
- **Dictionary Management**：字典类型 + 条目 管理（列表/创建/编辑/启用/禁用/排序）
- **Operation Log Page**：只读查询（time/user/operation/resource/result/requestId/correlationId），**无修改/删除**，不展示敏感内容

## 13. Reference Product Full-stack

## 27. Architecture Risks

1. **前端资产粒度**：5 个 asset 若粒度不当（过细→大量空资产；过粗→硬编码）→ 实施期以真实消费者为准调整
2. **生成项目结构**：frontend/ 并列加入 vs backend/ 子目录重构 → V0.5 选并列（兼容），但长期 monorepo 布局需 V0.6+ 决策
3. **前端版本漂移**：Element Plus/Vite/Vue 版本若散落模板 → 单点 BOM 化（lockfile + 集中配置）
4. **管理 API 扩面风险**：User/Role/Menu 等管理接口是权限敏感面 → 全部走 @RequirePermission + 测试 403
5. **Playwright 稳定性**：16 场景在 CI 的稳定性 → 用稳定选择器 + 后端 seed 确定性数据
6. **前端 Conformance 误报**：no-direct-axios 规则可能误伤 → 规则按 package 边界配置
7. **工作量大**：6 WP 横跨前后端 + 测试 + E2E → 按依赖图分阶段交付，每 WP 独立可验收
